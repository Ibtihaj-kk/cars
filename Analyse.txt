SYSTEM ANALYSIS PROMPT: BUSINESS PARTNER (VENDOR) MODULE
================================================================================

OBJECTIVE:
Conduct a comprehensive analysis of the existing Business Partner module's
architecture, flow, and logic to identify gaps and modifications needed for
implementing the multi-vendor self-service registration system.

================================================================================
1. CURRENT STATE ANALYSIS
================================================================================

Investigate Existing Business Partner Module:
- What is the current method of vendor/business partner creation? 
  (Admin-only, API, manual entry)
- What data model exists for business partners? 
  List all fields, status flags, and relationships.
- How are user accounts linked to business partner records?
- What approval/status workflow currently exists (if any)?
- What is the current authentication and authorization structure?

================================================================================
2. REGISTRATION FLOW ANALYSIS
================================================================================

Current vs. Desired State Mapping:

PUBLIC REGISTRATION ENDPOINT:
- Does one exist? If not, what's the closest equivalent?

FORM HANDLING:
- How are business partner records currently created?
- Analyze controllers/services involved in partner creation.

USER ACCOUNT CREATION:
- How are user credentials stored and linked to partner records?

REDIRECTION LOGIC:
- Trace post-submission redirects in current flows.
- Document all redirect paths and their conditions.

EMAIL NOTIFICATIONS:
- What email triggers exist in registration-related processes?
- What templates are available?

Specific Checks:
- Where would the new public registration form integrate?
- How will the IsApproved/ApplicationStatus field be added and managed?
- What validation rules need modification for self-registration?

================================================================================
3. AUTHENTICATION & SESSION ANALYSIS
================================================================================

Login Flow Examination:
- How does the current login process work for business partners?
- What role/permission system is in place?
- How are users redirected post-login based on roles?
- Where are session variables set (user type, permissions, partner ID)?

Approval Check Integration Points:
- Identify where to inject the IsApproved check in authentication flow.
- Determine how to modify post-login redirection for unapproved vendors.
- Map session initialization process.

================================================================================
4. DASHBOARD & UI ANALYSIS
================================================================================

Current Dashboard Structure:
- What components/menus exist on business partner dashboard?
- How are features/permissions currently controlled in the UI?
- What notification/message system is available?

Conditional Access Implementation:
- How to implement "under review" banner/notification?
- Which dashboard features should be disabled for unapproved vendors?
- How to toggle feature access programmatically (frontend & backend)?
- What UI components need conditional rendering logic?

================================================================================
5. ADMIN INTERFACE ANALYSIS
================================================================================

Existing Admin Tools:
- How are business partners currently managed in admin panel?
- What approval/rejection mechanisms already exist?
- What notification systems are available for admin actions?

Modification Requirements:
- Where to add approval/rejection controls in admin interface?
- How to trigger email notifications upon status change?
- What audit trails need to be maintained?
- What admin dashboard updates are needed?

================================================================================
6. SECURITY & DATA FLOW ANALYSIS
================================================================================

Security Considerations:
- How is data sanitized in current registration/update flows?
- What rate-limiting or anti-spam measures exist?
- How are uploaded documents handled and secured?
- What CSRF, XSS, and SQL injection protections are in place?

Data Flow:
- Trace complete data flow from registration to dashboard access.
- Identify all database writes/reads in the process.
- Map API endpoints and their current purposes.
- Document data transformation points.

================================================================================

EXTERNAL SERVICE DEPENDENCIES:

THIRD-PARTY INTEGRATIONS:

DATABASE DEPENDENCIES:

- Transaction boundaries

================================================================================
8. GAP ANALYSIS & RECOMMENDATIONS
================================================================================

Document:

MISSING COMPONENTS:
1. Public vendor registration portal
2. Self-service credential management
3. Automated approval workflow
4. Vendor status notification system

MODIFICATION POINTS:
1. Authentication controller - add approval check
2. Business partner controller - add public endpoints
3. Dashboard controller - add conditional rendering
4. Admin controller - add approval interface

DATA MODEL CHANGES:
1. Add approval_status field to partners table
2. Add application_date field
3. Add rejection_reason field
4. Add last_status_change field

PERMISSION/ROLE UPDATES:
1. New "Unapproved Vendor" role
2. Modified "Approved Vendor" role permissions
3. Admin approval permissions

UI/UX CHANGES:
1. Registration form design
2. Dashboard conditional UI
3. Admin approval interface
4. Status notification components

TESTING REQUIREMENTS:
1. Registration flow testing
2. Approval workflow testing
3. Security vulnerability testing
4. Performance testing under load

SPECIFIC RECOMMENDATIONS:

1. FIELD ADDITION:
   - Add `approval_status` ENUM('pending','approved','rejected') to partners table
   - Default value: 'pending'

2. REGISTRATION CONTROLLER:
   - Create new PublicVendorController for registration
   - Extend existing AuthController for login modifications

3. REDIRECTION LOGIC:
   - Modify login success redirect based on approval_status
   - Unapproved vendors → Dashboard with restrictions
   - Approved vendors → Full dashboard access

4. FEATURE TOGGLING:
   - Implement permission middleware checking approval_status
   - Create Vue/React mixin for frontend feature disabling
   - Use v-if / conditional rendering for UI elements
